# ✔️ معیار پذیرش ایجنت QA — Definition of Done

یک دور تست روی یک Use Case/فیچر «تمام‌شده» تلقی نمی‌شود مگر:

## پوشش سناریو
- [ ] تمام سناریوهای مرتبط در `docs/QA/Test-Plan.md` برای آن ماژول اجرا شده‌اند (مسیر موفق + حداقل یک مسیر خطا).
- [ ] سناریوهای امنیتی/حساس (Rate Limiting، RBAC، Privacy Proxy، Soft Delete) بدون استثنا پوشش داده شده‌اند.
- [ ] سناریوهای Edge Case (داده تکراری، ورودی نامعتبر، انتقال وضعیت غیرمجاز) بررسی شده‌اند.

## کیفیت گزارش نقص
- [ ] هر Bug دارای Repro Steps شفاف، رفتار مورد انتظار (با ارجاع به سند مربوطه)، رفتار مشاهده‌شده و شدت است.
- [ ] Bug های Critical/High بلافاصله به ایجنت مسئول (Backend/Frontend) و کاربر پروژه اطلاع داده شده‌اند، نه فقط ثبت در فایل.
- [ ] هیچ Bug تکراری (Duplicate) بدون بررسی سابقه ثبت نشده.

## انطباق با قرارداد
- [ ] پاسخ‌های API تست‌شده دقیقاً با ساختار `ApiResponse<T>` سند ۰۴ مطابقت دارند؛ هر انحراف به‌عنوان Bug ثبت می‌شود، نه نادیده‌گرفتن.
- [ ] کدهای خطای مشاهده‌شده با رجیستری سند ۰۴ یکی هستند؛ کد خطای مستندنشده = Bug.

## مستندسازی
- [ ] `docs/QA/Test-Plan.md` با هرگونه سناریوی جدید کشف‌شده حین تست به‌روزرسانی شده است.
- [ ] در صورت ابهام در معیار پذیرش یک Use Case، «سند ناقص» گزارش و از ادامه‌ی حدسی تست خودداری شده است.
- [ ] نتیجه نهایی (Pass/Fail per سناریو) برای فاز جاری در دسترس ایجنت‌های دیگر و کاربر پروژه است.
