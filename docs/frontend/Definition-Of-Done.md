# ✔️ معیار پذیرش ایجنت Frontend — Definition of Done

هیچ صفحه/ویژگی «تمام‌شده» تلقی نمی‌شود مگر:

## هماهنگی با Backend
- [ ] تمام داده‌های نمایشی دقیقاً از DTO مستند در `docs/04-Api-Contract.md` می‌آیند؛ هیچ فیلد فرضی/Mock باقی نمانده.
- [ ] پاسخ خطا (`success:false`) با استفاده از `message` و `errors` به فارسی و در جای مناسب فرم/صفحه نمایش داده می‌شود.
- [ ] برچسب‌های Enum (وضعیت آگهی، شیفت کاری، نوع بیمه و ...) دقیقاً معادل سند ۰۲-Domain-Glossary است.

## احراز هویت و امنیت
- [ ] Access Token با انقضای کوتاه مدیریت و Refresh Token طبق الگوی امن (سند ۰۵) چرخانده می‌شود.
- [ ] مسیرهای محافظت‌شده بر اساس نقش کاربر (Admin/CompanyManager/Candidate) Guard شده‌اند.
- [ ] هیچ شماره موبایل کامل کارفرما/کارجو در DOM یا Network Tab قابل مشاهده نیست جز برای صاحب همان اطلاعات.

## کیفیت UI/UX
- [ ] صفحه در حالت RTL و فونت فارسی به‌درستی نمایش داده می‌شود.
- [ ] فرم‌ها دارای Validation سمت کلاینت هم‌راستا با قوانین بک‌اند هستند (بدون تناقض پیام خطا).
- [ ] حالت‌های Loading، Empty State و Error State برای هر لیست/فرم پیاده‌سازی شده‌اند.
- [ ] صفحه در Breakpoint موبایل و دسکتاپ حداقل به‌صورت دستی تست شده.

## کیفیت کد
- [ ] Type Safety کامل (بدون `any` غیرضروری) در ارتباط با DTOهای API.
- [ ] فراخوانی‌های API از طریق لایه مرکزی RTK Query انجام می‌شود، نه `fetch`/`axios` پراکنده.
- [ ] Lint/Build بدون خطا.

## مستندسازی
- [ ] آیتم مربوطه در `docs/frontend/Tasks.md` تیک خورده است.
- [ ] در صورت نیاز به فیلد/اندپوینت جدید که در سند ۰۴ نیست، درخواست به‌روزرسانی سند قبل از پیاده‌سازی ثبت شده (نه Mock کردن).
